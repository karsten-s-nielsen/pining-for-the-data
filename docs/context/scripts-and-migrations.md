# Scripts & migrations — inventory and audit trail

> Class-2 context for the `scripts/` bullet of [AGENTS.md](../../AGENTS.md). AGENTS.md keeps the terse role summary; this file is the full inventory + the completed-migration audit trail.

`scripts/` — One-shot ops scripts, grouped by role:

- Per-provider load + post-load verify pairs: `upload_gradient_wc2022.py` / `verify_gradient_load.py`, `upload_idsse_bundesliga.py` / `verify_idsse_load.py`. StatsBomb has two source-family loaders sharing one verify: `upload_statsbomb_club.py` (commercial 360, `provenance="original"`) and `upload_statsbomb_open.py` (open-data tournaments, `provenance="redistributed"`, ADR 0012; fetch+cache the real feed, coherence pre-flight, same-tier skip-and-report players) / `verify_statsbomb_load.py`
- Owner-tier SkillCorner canonical ingest (Parquet/zstd, ADR 0011) — two source-family adapters sharing one verify: `upload_skillcorner_raw.py` (raw-JSON family: Champions League, Premier League 25/26) and `upload_skillcorner_parquet.py` (parquet-processed family: Real Madrid, Premier League 24/25), both `format_version=2` and skipping defective matches (missing a required role, or zero-byte tracking) up front via `partition_ingestible`; `verify_skillcorner_canonical_load.py` (canonical post-load HTTP verify). The legacy v0.3.0 RM loader `upload_skillcorner_realmadrid.py` / `verify_skillcorner_realmadrid_load.py` is retained (RM was migrated in place to the canonical set)
- Public-tier SkillCorner Open Data (A-League Men 2024/25, MIT — the original public redistribution): `upload_skillcorner_opendata.py` / `verify_skillcorner_opendata_load.py`. Competition-agnostic and idempotent (fetches the opendata repo anonymously, resolving Git-LFS pointers for the `*.jsonl` tracking via the media host with `sha256`/`size` verification, skips already-live ids), it redistributes each match's four artifacts as-is at `visibility=public`, `provenance=redistributed`, and (re)builds the public `players.json` across ALL opendata matches, skip-and-reporting any player id that collides with the owner/private index (never re-tiered silently). Pure logic in `formats.skillcorner_opendata`; reuses `players_from_meta` + `derive_players`
- Shared: `_verify_http.py` (HTTP helpers the verify scripts import), `regenerate_schemas.py` (drift-tested in CI), `verify_match_index_fields.py` (cross-provider live verify of the competition/season fields and `artifact_meta` through the API; `--full-hash` downloads every artifact — ADR 0013)
- Completed one-shot migrations against live S3 state, retained as the audit trail for changes already applied. Each one's behaviour on a re-run since ADR 0013 (`artifact_meta` on every entry):
  - `backfill_skillcorner_artifacts.py` (legacy array-form artifacts → canonical object form): touches only entries whose `artifacts` is a list; no live entry is in that form, so a re-run changes nothing.
  - `migrate_skillcorner_tracking_parquet.py` (owner-tier tracking → nested Parquet, events/physical → zstd, freeze dropped — ADR 0011; stored-object-gated): its conversion branch refuses an entry that carries `artifact_meta`; its `format_version: 2` self-heal sweep deletes only the two fixed legacy object names, which are not in a canonical entry's `artifacts`.
  - `migrate_pff_to_gradientsports.py` and `migrate_gradientsports_slug.py` (the two provider-slug renames): `copy_object` keeps the bytes, so the hashes stay valid, and the index rewrites copy every entry whole; their source prefixes are empty, so a re-run copies nothing.
  - `backfill_skillcorner_opendata_lfs.py` (re-upload the resolved LFS blob for public opendata tracking objects stored as 133-byte Git-LFS pointers — range-probes the body, verifies `sha256`/`size`): each replaced object also updates its entry's `artifact_meta` and `updated_at` in one `IfMatch` write of `matches.json`; on a `412` it reports the replaced objects and exits 1.
  - `backfill_match_competition_and_artifact_meta.py` (competition/season fields and `artifact_meta` on every live entry, two passes — ADR 0013): applied with `--apply` by the script file with sha256 `faf2ccf6b4f44605ad62e98bdad4c59a90f39b05d2cad60e397c6bbace37c93e`; it changed all 1307 live entries (gradientsports 64, idsse 7, skillcorner 909, statsbomb 327), and every raw id it read was an `int` or a `str`. A re-run changes no entry and no `updated_at` while the stored bytes are unchanged.
- Data: `idsse_figshare_manifest.json` (committed md5 manifest for the pinned figshare release)
